# Security review, 2026-09-30

Pre-submission review of Tesoro's on-chain code (Colosseum deadline 2026-10-12). Testnets only, no real value, but the money rules of `CONTEXT.md` and ADR 0001 must hold and the code will be read. All statuses below are as of branch `worktree-agent-a3128b9c4d0555ad9`; nothing was deployed.

## Scope

| Component | Path |
|---|---|
| tesoro_core (ledger, native Positions and simSOL custody, source authorities, Matches, fees, Backing) | `programs/tesoro_core` |
| Block Puzzle (Private Ephemeral Rollup game, CPI settlement) | `programs/block_puzzle` |
| Hold'em (Private Ephemeral Rollup game, CPI settlement) | `programs/holdem` |
| sim_lst (simulated LST) | `programs/sim_lst` |
| LayerZero OApp | `bridge/programs/tesoro_bridge` |
| EVM contracts | `contracts/src` (`PositionVault`, `PositionVaultOApp`, `SimLST`, adapters, mock endpoint; the spike OApp only noted) |

Not reviewed: `keeper/`, `app/`, deploy scripts, the MagicBlock, LayerZero and Pyth programs themselves (read where their behaviour matters).

## Method

1. Read `CLAUDE.md`, `CONTEXT.md`, the ADRs, the core, cross-chain, game and spike docs, then every source file in scope.
2. Walked each program against the six Solana patterns of the vulnerability scanner (arbitrary CPI, PDA validation, owner checks, signer checks, sysvars, introspection) plus arithmetic, reinitialisation, CPI reload, remaining-accounts validation, replay, griefing and privacy.
3. For each suspected issue, wrote the smallest failing test first (LiteSVM for programs, forge for contracts), ran it on the unfixed build, then classified. Where LiteSVM cannot model the mechanism (there is no delegation, permission or VRF program), the limit is stated in the finding.
4. Implemented minimal, layout-compatible fixes for Critical and High findings, one commit each, keeping the proof tests (now passing).
5. Measured compute units of the hot instructions with LiteSVM.
6. `program_autofixer` (anchor) was run on the changed regions of both game programs (the delegation helper, the permission helper, `create_match` and its context, `init_permission`): no issues, `require_another_tool_call_after_fixing: false`. Not run on the full files, which are unchanged elsewhere.

Verification on the branch: `cargo test --workspace` green (all suites), `cargo fmt --check` clean, `cargo clippy --workspace --all-targets -- -W clippy::all` shows only pre-existing Anchor macro warnings (`unexpected cfg solana`, deprecated `realloc`), `forge test` 48 passed.

## Item-by-item verdicts

### Solana

| Item | Verdict |
|---|---|
| Account validation: owner, signer, PDA seeds and bumps, `has_one` | Pass in tesoro_core, sim_lst and the bridge: every account is `Account<T>` / `Signer` / `Program<T>` with `seeds` and a stored canonical bump; `find_program_address` appears only where a bump is first derived (`open_session`, `create_match`, `init_store`). Manual `create_program_address` in `util.rs` and `native.rs` uses the stored bump and compares the key. Fail in the game programs for F-01 and F-02 (fixed). |
| Missing signer checks | Pass. Admin, oracle, source authority, owner, holder, backer, player and game authority are all `Signer`. Permissionless instructions (`accrue_native_yield`, `open_holding`, `expire_offer`, `apply_locked`, `seal`, `settle`, `finalize`) only move state that is fully determined by on-chain data. |
| Arbitrary CPI / unchecked program ids | Pass. Token CPIs check `token::ID`; game programs use `Program<TesoroCore>`; bridge uses `Program<TesoroCore>` and the endpoint constant. The delegation and permission programs are address-constrained. |
| PDA authority misuse | Pass. `["authority"]` PDAs sign only `settle_match`, `refund_match`, `extend_match_deadline`; custody PDA signs only vault transfers. |
| Type cosplay / discriminators | Pass. `Account<T>` everywhere, including remaining accounts (`Account::try_from` plus a PDA re-derivation from the stored bump). |
| `remaining_accounts` | Pass. Native redeem / unlock: exactly five, custody PDA re-derived, `custody.position == position`, vault equals `custody.vault`, destination mint and owner checked, pool equals `custody.pool` (and is sim_lst-owned), token program equals `token::ID`, duplicates rejected. Entries: at most two Holdings, canonical order, each owned by the entrant and drawn from. Payouts: exactly two accounts per payout, recipient key equals the payout, Holding source equals the payout's. |
| Arithmetic | Pass. Checked or `u128` with checked ops throughout; no `unwrap()` in program code; `overflow-checks = true` in release. Directions: Advance floors, repayment ceils, `covered` and pro rata floor, redemption units floor, custody shares floor on payout and ceil on reserve. Protocol-unfavourable only in fee dust (F-14b). |
| Reinitialisation / close | Pass. All accounts use `init`; `init_if_needed` only on admin-gated or oracle-gated singletons (`set_source_authority`, `set_price`), the bridge's `EvmLink` (needs a wallet signature) and `Claim`. Only `remove_source_authority` closes an account (to the admin). |
| CPI reload after mutation | Pass. Vault reloaded after each token CPI, custody written after payout, bridge reloads `core_source` after `redeem`. |
| Rent / lamport drains | Pass. No path moves lamports out of program accounts except the admin close. Permission rent is prefunded from the payer into accounts the program owns. |
| Replay / idempotency | Settle and refund: status machine (`Open`/`Active` to `Settled`/`Refunded`) plus `session.settled` / `finalized`. `apply_yield` and `apply_yield_from_source`: seq no-op. Native crank: byte-identical no-op. Bridge inbound: `Endpoint::clear` burns the nonce, then `locked_seq` / `last_yield_seq`. Bridge outbound: `unlock_sent`, `out_seq`, `units_sent` set in the same transaction. EVM side: F-04. |
| LayerZero peer / endpoint / seq | Pass. `params.sender` must equal the registered `PeerConfig` PDA derived from it; position id embeds the vault address and must match `params.sender`; `src_eid` must equal the header's; `init_store` pins the endpoint id. `lz_receive` reaches state only through a successful `clear`. The only remaining trust is the DVN set. |
| Privacy in the rollup (Deck, hole cards, Seed, moves) | Fail before F-01 / F-02 (delegation to a non-TEE validator; permission spoofable), pass after: Seed only in the memberless SeedVault until `begin_run` copies it into the Player's own Board; Boards are sealed and committed only when both runs are closed; the vault seed is zeroed before commit; Deck and Holes are wiped in `close_match`; no `msg!` in Hold'em, and the only one in Block Puzzle prints the Player's own move index; the VRF callback needs the scoped VRF identity signer (macro-injected); nothing is auto-committed. Board cards are copied to the public table only when the street is dealt. |
| Griefing | Block Puzzle: F-06, F-09. Hold'em: a Player can stall only within the 30 s turn clock and three missed turns forfeit; F-03 fixed. Backing: the Backer can cancel an Accepted Offer before use (F-12); a Player cannot pin a Backer's Gemas (expiry is permissionless). Settlement cannot be blocked by a missing Holding (anyone opens it). Unlock and yield cranks are permissionless. |

## Invariant verdicts (ADR 0001)

| Invariant | Verdict |
|---|---|
| Principal never pays Debt | Holds in the ledger (no function reads Principal after sizing an Advance; property-tested). Broken by donation to a native vault (F-05, open). |
| Redemption is at most accrued | Holds. Ledger: `redeemable_for` is floor pro rata of `covered - redeemed`; native: every payout re-checks `check_cover`; EVM: `ExceedsAccruedYield`. The oracle and the source authority can lie about yield but the EVM vault caps payouts at its own accrual. |
| Pots conserve | Holds. Payouts are the loser's lines minus fees plus the winner's entry (backed: Backer entry, then the Offer's split, remainder to the Backer); a model-based property test (`ledger_invariants`) checks per-Source conservation across Holdings, Pots and Reservations. |
| A backed Player never gains Debt | Holds. A Player is only ever credited won Holdings; Debt exists only on Sources of a Position, created by `take_advance` and `take_native_advance`, which require the Position owner. |
| A Backer is never charged beyond the Offer | Holds. The reservation is exactly `entry`; loss costs the entry and nothing else; the Player is never debited. |
| Settle once | Holds on both layers. |

## Decisions needed

1. **Redeploy of the fixed programs.** `holdem` (F-01, F-02, F-03) and `block_puzzle` (F-01, F-02) are upgradeable and their account layouts are unchanged; `holdem::create_match` gained two accounts (`config`, `tesoro_program`), so the app IDL was regenerated in this branch. Tables and sessions created on the old programs keep the old behaviour. Also ask the upgrade authority to whitelist the TEE validator per program in the delegation program.
2. **EVM vault redeploy (F-04).** The contract is not upgradeable, so the fix needs new `PositionVaultOApp` deployments (Hoodi, HyperEVM), `set_peer_config` for the new vault addresses on the bridge, `setPeer` on the OApps, and moving any open Position. Storage of existing state is unchanged (one new mapping appended). Until then, keep spacing `send_unlock` and `send_pay_yield` and send in seq order.
3. **F-05:** add a share counter to `NativeCustody` (layout change plus realloc of existing custodies), or accept the top-up and amend ADR 0001.
4. **F-06:** choose how an opener who has not begun is protected when a joiner arrives late.
5. **F-07:** whether plain `redeem` on non-native Sources should be refused.

## Residual risks

- **Trusted oracle and price feed.** `Config.oracle_authority` opens oracle Positions, fixes the issuance price of `take_advance` and writes the native `PriceFeed`. A wrong price mints too many or too few Gemas; Gemas are equal at the table but not at redemption, so mispriced Sources let a holder win real Sources' Gemas with worthless ones. Pyth is planned to replace the feed.
- **MagicBlock TEE trust.** Hidden state (Deck, Holes, Seed, Boards) is private only if the TDX attestation and the permission program hold. The Game programs now pin the validator but cannot verify attestation; clients must (S1 does).
- **LayerZero DVN trust.** Inbound messages are as honest as the configured DVN set; a compromised set could register Positions and yield for a registered vault. The EVM vault still caps payouts at its own accrual and only releases Principal on an Unlock from the registered peer.
- **Admin powers.** tesoro_core admin can register or replace Games (a Game authority can settle any of its Matches), set the fee up to a 50% cap, replace the oracle and the source authorities. The bridge admin registers peers (vaults). Program upgrade authorities control every program. sim_lst admin can change the rate, pause and fund the reserve; `SimLST` owner likewise.
- **Simulated tokens.** simSOL, simETH, the faucets and the accelerated yield clock are simulated (F-08) and labelled as such.
- **Delegation record.** The DLP checks the committing validator against the record only; program logic must never trust a Board or table state committed by any other validator (now enforced by the pin).
