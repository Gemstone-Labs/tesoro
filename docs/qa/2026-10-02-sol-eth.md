## Bugs found

Fixed on `qa/app-e2e-sol-eth-02-10-2026`:

1. **P1: a holder who never opened an ETH Position cannot redeem ETH-Sourced Gemas, and the Sheet says it worked** (still present from `docs/qa/2026-10-01.md` bug 1). Repro: `qsA` wins 900 ETH-Sourced Gemas from `qeC` in a Match, has never linked an EVM address, opens Wallet → Redeem → "Redeem 1,689": the native row redeems ("Redeemed 1 Source into simSOL" `4FjkV9vjSN…19rBV9Kp`), `redeem_to_evm` fails `Custom 6019` NoEvmAddress (`3Nc6ea74ib…CtG5Ke5v`, 12:06:11), no tracker, and the ETH rows stay redeemable but unreachable (350 Gemas of `qsA`, 360 of `qsC`). Every winner of ETH-Sourced Gemas without an ETH Position hits this, which is the normal cross-chain case. Fix (commit `8f2643b`): `redeemEthHoldings` now runs `ensureEvmLinked` first (`app/src/app/wallet/EthPositions.tsx:660–667`) and `RedeemForm` raises "Your EVM wallet is not ready yet" instead of silently skipping the ETH rows when the EVM context is missing (`app/src/app/wallet/NativePositions.tsx:314–316`). Verified live on `qsC` (link + two `redeem_to_evm`, Hoodi payout 0.000505 simETH); `tsc --noEmit` and eslint on both files clean. No unit test: the path needs a signer and RPC (not stubbed in the repo's existing tests).

Not fixed (report only):

2. **P2: one transient network error zeroes a whole Block Puzzle run.** Match `3581889662060` (`qsG` vs `qeE`, 1,000): `qsG` scored ~100 on screen, the host's network blipped (`net::ERR_NETWORK_CHANGED`), the move batch failed with "failed to get recent blockhash: TypeError: Failed to fetch", the page showed "Some moves were not accepted" and the Match ended as a Draw "Equal scores: both entries were returned" (0–0). Cause: `RunSubmitter.flush` stores the first error in `this.error` and every later batch returns early (`app/src/lib/chain/match-flow.ts:290–301`); `finish` swallows its own error (`:306`). A retry (re-send the same batch on a blockhash/fetch failure, only give up on a program error) would keep the run. In a real match the Player loses their stake share on a Wi-Fi hiccup.
3. **P2: a raw transaction error stays under a settled result** (still present, bug 4 of the previous report). `qeE`'s result on Match `3581887481018` (Won +900) shows `base tx failed mjyeWsaAh2…: {"InstructionError":[0,{"Custom":0}]}` (the losing racer of two clients' `open_holding`, `mjyeWsaAh2…ay77rZdV` FAIL 12:25:55). `MatchView` keeps `error` after the phase becomes `result` (`app/src/components/match/MatchView.tsx:122`, `:245`, `:402`).
4. **P3: duplicate failing transactions on every Match** (previous bug 6, unchanged): each Hold'em table gets two failed `DelegateMatch`/`CreateMatch` (36 s and 76 s after create) from each client (`qsA` `5szuT7cyua…cgsaCPfF`, `32sRym8zPb…85tWpR5x`; `qeE` `4FFLkpVVyt…GrDz1nkX`, `3Vs75n47R2…CFWLhFx8`), failed `Finalize` (`5XhfrqvTj5…ZutUwDry`, `5moYA5oSNZ…podcjKFR`), and Block Puzzle `Settle`/`OpenHolding` losers (`5xs6km3n1L…9XrbNziv`, `3yKHfr6f4j…9XFY18gC`, `yvRUJyypKJ…eQdXnzFw`, `5YT2eZXE1T…Vze2x3pR`). Each costs a base fee.
5. **P3: the Wallet's Redeem note shows the underlying asset amount labelled as simETH.** `qeD`: "Redeem pays 2,918 ETH-Sourced Gemas → 0.01063 simETH"; the Hoodi balance rose 0.004122558 simETH (the vault's simETH is 2.55 ETH, so 0.01063 is ETH). `redeemPayoutWei` returns the Source's underlying amount (`app/src/lib/chain/eth.ts:531`) and the note prints it with the simETH symbol (`app/src/app/wallet/EthPositions.tsx:630`). Divide by the vault rate or label it "worth 0.01063 ETH".
6. **P3: stale totals for about a minute after a transaction.** After `return_own` (11:14:20) the card showed Debt 624 but Total Balance 2,878 / Pending 1,024 (the true figures, 2,478 / 624, arrived on a fresh load ~1 min later); after a settle the header showed 1,978 while the Wallet showed 2,878. List cache (`gpa`), already known; it makes the Return and the result look wrong for a moment.

The simulated clock is slowing down as `base_rate` stands further from now (needs the program/contract re-base).

Get Gemas in your Wallet" (`qeF`, screen `j2c-qeF-lobby-away`). The step continues only when the Wallet or `/wallet/opening` is opened, in a browser with that tab open; `qeD` waited 14 min for a visit.
