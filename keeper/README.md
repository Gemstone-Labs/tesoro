# Keeper

Off-chain process that keeps the devnet demo moving without a human. Every job is idempotent, permissionless on chain (the keeper is just a fee payer) and logs one line per action.

```
pnpm --filter @tesoro/keeper start            # loop, every 20 s
pnpm --filter @tesoro/keeper start --once     # one pass, then exit
pnpm --filter @tesoro/keeper start --once --dry-run   # say what it would do, send nothing
pnpm --filter @tesoro/keeper typecheck
```

Flags / env: `--interval <secs>` (`KEEPER_INTERVAL_SECS`, 20), `--max-sol-per-hour <n>` (`KEEPER_MAX_SOL_PER_HOUR`, 0.5), `--rpc <url>` (`KEEPER_RPC`, default `https://rpc.magicblock.app/devnet`; the public devnet RPC rate-limits), `KEEPER_KEYPAIR` (`~/.config/tesoro/keeper.json`; `KEEPER_SECRET_KEY` holding the file's JSON array wins when set), `TESORO_IDL_DIR`, `KEEPER_RPC_TIMEOUT_MS` (30000: each RPC request gives up after this), `KEEPER_JOB_LIMIT_SECS` (120: a job still running after this no longer holds up the others and is skipped until it finishes).

Cluster: at startup the keeper checks the genesis hash of `KEEPER_RPC` and `KEEPER_GPA_RPC` and refuses to start unless both are Solana devnet. The Hoodi RPC must answer chain id 560048: a different chain stops the start, an unreachable one is rechecked by the eth job before it sends. The compromised key `AXwY…` (`~/.config/solana/id.json`) is refused as payer or oracle.

Bridge / Ethereum: `--max-lz-fee-sol` (`KEEPER_MAX_LZ_FEE_SOL`, 0.005: refuse a Solana-side LayerZero send whose quote is higher), `--max-lz-sol-per-hour` (`KEEPER_MAX_LZ_SOL_PER_HOUR`, 0.05: LayerZero fees paid in any rolling hour), `--hoodi-rpc` (`KEEPER_HOODI_RPC`, `https://ethereum-hoodi-rpc.publicnode.com`), `--hyperevm-rpc` (`KEEPER_HYPEREVM_RPC`, `https://rpc.hyperliquid-testnet.xyz/evm`), `KEEPER_STATE_DIR` (`~/.cache/tesoro-keeper`: the history cursor lives there), `KEEPER_LOOKUP_TABLES` (address lookup tables for chunks and other wide transactions).

Payer: `~/.config/tesoro/keeper.json` is created on first run (never in the repo). The keeper never funds itself: a payer under 0.1 SOL is logged at start and topped up by hand. Fees and rent it spends are tracked in a rolling hour; at the cap, actions are skipped and logged. 429s are retried with exponential backoff inside each RPC call, and the loop doubles its delay (max 5 min) after a rate-limited pass.

## Hosting and liveness

Hosted keys come from env secrets, never from the image: `KEEPER_SECRET_KEY`, `KEEPER_ORACLE_SECRET_KEY` (the JSON arrays of the key files) and `KEEPER_EVM_PRIVATE_KEY` (`src/keys.ts`). `KEEPER_KEYS_FROM_ENV=1` (set in the image) makes a missing `KEEPER_SECRET_KEY` fatal instead of minting a new payer. Each pass logs `alive pass=<n> took=<s>`; a watchdog exits the process when no pass finishes in `KEEPER_WATCHDOG_SECS` (2400), for the host to restart it; `KEEPER_HEALTH_PORT` serves `GET /healthz` (200 alive, 503 stale) on all interfaces, or only on `KEEPER_HEALTH_HOST` when set (e.g. `127.0.0.1` on a VPS with a public IP). Image: `keeper/Dockerfile`; Fly.io config: `keeper/fly.toml`.

## Alerts

The last job of each pass (`src/alerts.ts`, `src/alerts-job.ts`) emails both founders through the app (`POST <NOTIFY_URL>alert`, `NOTIFY_SECRET`; the app mails `ALERT_EMAILS`, so the Resend key and the recipients stay in the app and the keeper holds no mail secret). Off when `NOTIFY_URL` or `NOTIFY_SECRET` is unset. Three triggers: commits pending longer than `ALERT_COMMIT_PENDING_SECS` (1800); a job that threw `ALERT_JOB_FAILS` (5) passes in a row or had no successful run for `ALERT_JOB_STALE_SECS` (1800); a key under its minimum balance: SOL of the keeper payer, oracle (`ALERT_ORACLE_SOL_ADDRESS`) and relayer (`ALERT_RELAYER_SOL_ADDRESS`) with `ALERT_MIN_SOL_KEEPER|ORACLE|RELAYER` (0.3 / 0.2 / 0.3), and the native balance of the keeper EVM key (`ALERT_KEEPER_EVM_ADDRESS`, default from `KEEPER_EVM_PRIVATE_KEY`) and relayer EVM key (`ALERT_RELAYER_EVM_ADDRESS`) on Ethereum (`ALERT_MIN_ETH_KEEPER|RELAYER`, 0.01) and HyperEVM (`ALERT_MIN_HYPE_KEEPER|RELAYER`, 0.05). A key with no address set is not watched; a balance that cannot be read is skipped. One mail when a condition starts, a reminder at most every `ALERT_REMINDER_SECS` (14400) while it lasts, one "recovered" mail when it clears; a mail the app did not take is retried next pass. State is in memory, so a restart re-announces a condition still active.

## Jobs

1. **Match hygiene** (every Match in tesoro_core; Block Burst in `src/blockpuzzle.ts`, Hold'em in `src/matches.ts`)
   - **Settling and Refunding Matches, every Game** (`src/settle.ts`): once a Match's run has started (`settle_match` or `refund_match`), the keeper runs `match_chunk` until the run is done and then `close_match`. A chunk carries the baskets and spills of the Accounts it credits, and for the next steps the book and checkpoint pages of each Source (and, for a fee cut, the SourceState, Position and the custody with its rate account); `src/chunks.ts` is a port of `MatchRecord::sources_ahead` and `src/supply.ts` assembles the accounts. The steps per chunk (`KEEPER_CHUNK_STEPS`, 6) shrink until the transaction fits 1,232 bytes and 64 accounts; with `KEEPER_LOOKUP_TABLES` (comma separated address lookup tables) it compiles a v0 message. A chunk that reports `blocked` (a credit found no slot) makes the keeper `grow_store` the spill of the Account that is full, then run the chunk again. `close_match` receives the spill of every Account that still holds room for the Match plus both Players' counters. Refunds the Game logic below asks for go through `refund_match` (anyone may once the deadline passed).
   - Block Burst (open_session / join_session flow; the Seed lives in a SeedVault in the TEE, so the keeper never needs it):
     - Open Match nobody joined, Queue window (1 h) over: `refund_match`. Its opener Board and SeedVault stay delegated (the rollup cannot see the base Match).
     - Joined on tesoro_core but not bound to the Session (an older client): `join_session`, inside the Match's 1 h window; after it, `refund_match`.
     - Both Boards in the rollup: a free simulation of `seal` (works from a non-member) says whether both runs are closed. If so, or if both deadlines passed, `seal` + `commit_boards` in the TEE, then `settle` on the base layer (one pass). Otherwise it logs when the deadlines fall.
     - A Board still on the base layer (its Player never delegated) whose deadline passed (opener: the Queue window, joiner: 24 h): `delegate_opener` / `delegate_joiner`, then seal + commit + settle: that Player forfeits, per the program. Before every seal the keeper reads the two Board permissions and the SeedVault permission in the rollup and creates any that is missing, each as its own retried step: `commit_boards` closes all three in the same transaction as `seal`, so one missing permission fails both.
     - Neither Board delegated and the joiner's 24 h deadline passed: `claim_timeout` (both forfeit, both entries refunded). Both committed and sealed but not settled: `settle`.
     - A Session in the pre-`open_session` layout (cannot be decoded by the current program) or a joined Match with no Session: waits for the Match deadline, then `refund_match`.
     - Rollup attempts per Match are throttled to one a minute.
   - Hold'em (`src/holdem.ts`, tables like Trading Duel's): no Assignment: `assign_match` to an Idle table, or `refund_match` at the Match deadline. The table is public, so the keeper reads it: `begin_match`, `seat_players`, `expire_start` past the start deadline; in play `deal` when the oracle's answer is in and `claim_timeout` once the hand's clock ran out (it checks or folds an idle Player, forfeits after three misses, refunds a hand whose randomness never came); `commit_table` once per result; `finalize` from the committed table's ring. Table upkeep per pass: `wipe_seats`, `reset_table`, `release_slot`, `void_table`, Sponsor refill. It never reads a Hole seat.
   - Trading Duel (`src/duel.ts`, pure decision in `duelStep`; `src/tables.ts`, pure `tableStep`): Matches run on persistent tables (`docs/games/trading-duel.md`). Per unsettled Match: no Assignment: `assign_match` to an Idle table (done by the table scheduler, see "Table scheduler" below; operator = the keeper key); base's committed table can settle it: `finalize` (reads the result ring); Idle at the Match's epoch: `begin_match`; Waiting with the Books missing: `open_seats`; Waiting past the start deadline: `expire_start` (refund in the ring); Live: one `tick` per pass, `end_match` after `KEEPER_DUEL_END_GRACE_SECS` (2) once a simulation says it is possible; Over and dirty: `commit_table` (once per result). Table upkeep, once per pass (`maintainTables`, independent of any Match): `commit_table`, `close_seats`, `reset_table` (30 s after the end), `release_slot` (tesoro_core's receipt 60 s old), `void_table` (tesoro_core refunded the table's Match); `refillSponsorIfLow` moves `KEEPER_DUEL_FUEL_AMOUNT` (50,000,000 lamports) from Fuel `KEEPER_DUEL_FUEL` (0) when the Sponsor is under `KEEPER_DUEL_SPONSOR_FLOOR` (20,000,000). The keeper key must be the Game's operator (`set_config`).
2. **Backing hygiene**: `expire_offer` for Open Offers past `expires_at` and Accepted Offers past `use_by`, releasing the Backer's reserved amount (an Offer with a Backing Ticket open waits until the Ticket job cancels it). Requests have no expiry instruction in tesoro_core (only the Player can `cancel_request`) and hold no reservation, so they are only counted.
3. **Price feed** (`src/price.ts`): the oracle key (`KEEPER_ORACLE`, `~/.config/tesoro/oracle.json`) publishes SOL/USD with `set_price` whenever the on-chain `PriceFeed` is older than 50 minutes (`KEEPER_PRICE_REFRESH_SECS`; so at least hourly; Advances reject a feed older than 24 h). Price: Pyth Hermes (update at most 2 minutes old, confidence within 2%), CoinGecko and Coinbase spot are all asked; two or more valid answers give their median, a single one is used only within 25% of the last on-chain price. With no usable price nothing is published, so the feed ages and Advances stop at 24 h rather than being priced from a re-stamped old value. It is a **devnet price feed**, a stand-in until Pyth is read on chain. The oracle pays that fee, so keep it funded.
4. **Native yield: no job.** A Solana-native Position's Debt, redeemable amount and free yield are computed from the clock by the instruction that needs them (ADR 0010), so nothing is cranked and the keeper never touches it.
5. **Bridge relays, Solana side** (`src/bridge.ts`, `src/lz.ts`; flow in `docs/cross-chain.md`). Reads every `BridgePosition` and `Claim` of `tesoro_bridge` and moves what is ready, each step guarded by the bridge's own tracking (`opened`, `applied_yield_seq`, `unlock_sent`, `Claim.units_sent`), so a repeated pass is a no-op:
   - PositionLocked delivered, not applied: `apply_locked` (the keeper pays the core Position's rent; waits, with a log line, while the owner's EVM address is not linked to an Account).
   - YieldAccrued delivered and newer than the applied one: `apply_yield` (with the Position's open Advance Source and its book and checkpoint pages, if any).
   - Position Unlocked in `tesoro_core` with Debt zero: `send_unlock`. Redemption Claim with units not yet sent (`redeem_to_evm`): `send_pay_yield`. Instant Redeem claim (`InstantClaim`, written when the store admin fills an ETH or HYPE order with `instant_redeem_to_evm`) with units not yet sent: `send_pay_instant`. Claims and InstantClaims have the same size, so they are read by discriminator.
   - The two sends pay the LayerZero fee in SOL from the keeper payer: the fee is quoted by simulating `quote_send`, refused above `--max-lz-fee-sol`, and counted against `--max-lz-sol-per-hour`. Every base transaction is simulated first, so a step that would fail is logged as `wait: ... would fail (...)` and costs nothing.
6. **EVM yield: no job.** An ETH or HYPE Position's Debt is computed by the vault (ADR 0010); anyone may call `reportYield(id)` on the vault (the Player's app does when they want Debt lowered) and the bridge job below applies the arrived report. The keeper holds no EVM sending key; `KEEPER_EVM_PRIVATE_KEY` only names an address whose balance the alerts watch.

Fixture (pre-upgrade flow: `both-runs-closed.ts`, `holdem-no-show.ts` and `turn-latency-spike.ts` open Matches with the Holdings client and do not run against the upgraded programs; they return with the game tickets 12 to 15): `pnpm --filter @tesoro/keeper exec tsx scripts/both-runs-closed.ts` plays a real devnet Block Burst Match up to "both runs closed" (test wallets from `~/.config/tesoro/block-puzzle-testers.json`) and stops, so the keeper does the seal, commit and settle.

## Admin scripts

`keeper/scripts/launch-admin.ts` prints (dry run by default) every `tesoro_core` launch init call in runbook order, with signer, named accounts and base64 data; `--execute` sends only the steps the single `--keypair` signs, never a Squads vault step (`docs/mainnet-runbook.md`, T-7 step 5). `register-game.ts`, `init-leaderboard.ts` and `whitelist-tee.ts` take `--keypair <file>` (no default key file), `--rpc`, `--cluster test|mainnet` (default test; the RPC must serve that cluster) and `--program tesoro_core=<ID>`; `fund-treasury.ts` and `withdraw-treasury.ts` are simSOL test-mode scripts and refuse mainnet. Shared parsing is `src/cli-args.ts`.

## Sharing

The keeper imports the app's IDL-based clients (`app/src/games/*/chain.ts`) and IDL JSON directly, so it cannot drift from them. It only needs `app/` to be installed (`pnpm install` at the root).

## Limits

- Private rollup state (Block Burst Boards, Hold'em tables) is unreadable to the keeper; it uses simulations and program-enforced clocks to decide. If the rollup rejects simulation from a non-member, the keeper waits for the deadline paths.
- Block Burst Matches are settled by the Player clients when they can; the keeper is the fallback. The forfeited-Board path (`delegate_*` + permission for a Player who never delegated) needs a 24 h wait (opener: 1 h) and is implemented from the app's `bringForfeitedBoardsIn` and the program, but not yet exercised on devnet.
- Wallet-signed steps stay with the user: `create_account`, `link_evm`, `take_advance` (owner + oracle), `redeem_to_evm` and `unlock`. Once they exist, the keeper does everything after them.
- `init_position` (the inbox record that must exist before `openPosition`) is not pre-created by the keeper; the app does it.

7. **Leaderboard seasons** (`src/season.ts`, spec "Season order"): once a season has ended (plus `KEEPER_SEASON_GRACE_SECS`, 600, so late settlements are in): (1) `fund_season_prize_native` / `_stake` for every route of the Economy settings whose prize escrow is on and not yet funded for this season (a stake pool that is behind is updated in the same transaction), and `fund_season_prize_evm` for ETH and HYPE routes; (2) `record_season` with the ranking recomputed from core's `MatchWon` events (the same event-CPI scan as the history writer, `seasonWinsFromChain`; a transaction that cannot be read stops the ranking, it never ranks on a partial scan), which freezes the prize budget from the Pool; (3) after the 48-hour window, `pay_season_rank` for every (rank, budget line) step not paid and not voided, three steps a transaction, making room in a winner's stores first; (4) `close_season` once every rank is paid or voided. The signer is whichever of the keeper payer and the oracle key `EconomyConfig.season_keeper` names (ticket 24 runs `set_economy`); the keeper skips the job, with a log line, when it holds neither. A season with no wins is rechecked every 30 minutes; every step is idempotent because the chain says what is left.
8. **Treasury** (`src/treasury.ts`): the Treasury Account holds the Gemas bought by Instant Redeem, in its basket. For each line of at least `KEEPER_TREASURY_MIN_GEMAS` (100) Gemas, largest first and at most `KEEPER_TREASURY_MAX_PER_PASS` (4) per pass, a free dry run finds how many of them their Source's yield has repaid (a Redeem pays only the repaid part) and the job redeems exactly that: `redeem_treasury` for Solana Sources (simSOL into the Treasury vault; staking tokens stay in the custody vault as the Treasury's own shares), bridge `redeem_treasury_to_evm` for ETH and HYPE Sources, whose Claim the bridge job then pays into the vault's own treasury with `send_pay_yield`. A line with too little repaid is left for 30 minutes. Set the Treasury up and fund it once with `keeper/scripts/fund-treasury.ts`.

## Table scheduler

One job (`tables`, `src/scheduler.ts`; the four Games are adapters in `src/scheduler-games.ts`) for Trading Duel, Hold'em, Block Burst Live and Vanguard. It runs first in every pass, before the Match job, whether or not any Match is open, and reads everything from the chain each pass, so a restart mid-step just repeats the step. Per Game it:

1. checks the keeper is the table `operator`, that the Sponsor exists and is delegated (creates it from `KEEPER_<G>_SPONSOR_INIT` lamports if that is set, else alerts) and delegates the configured Fuel;
2. upkeeps every table, one step per table per pass: `release_slot` (tesoro_core's receipt 60 s old), `void_table` (the table's Match was refunded), `commit_table` (dirty, or a result base does not show after 120 s, backed off), `close_seats`/`wipe_seats`, `reset_table` (30 s after the end, only after the end state is stored: `resetMayProceed` lives in the scheduler, the adapters cannot reset a table without it);
3. assigns the oldest joined Matches without an Assignment to Idle, seated tables with a free ring slot. A table is held for an Assignment only until that Assignment's start window closes, so an Assignment whose Match never began frees its table at once and the next Match goes there (its own Match is refunded by `finalize` when the table's epoch moves on, or by tesoro_core's deadline);
4. makes tables while Matches wait: `create_table`, `delegate_table`, `init_seats` (Hold'em, Block Burst, Vanguard), at most `KEEPER_TABLES_CREATE_PER_PASS` (2) new tables per pass and never past `min(KEEPER_<G>_TABLE_CAP, TableConfig.max_tables)`, keeping `KEEPER_<G>_TABLE_SPARE` (1) ready and `KEEPER_<G>_TABLE_MIN` (1) in all;
5. refills the Sponsor from Fuel `KEEPER_<G>_FUEL` (0) by `KEEPER_<G>_FUEL_AMOUNT` (50,000,000) when it is under `KEEPER_<G>_SPONSOR_FLOOR` (20,000,000);
6. every `KEEPER_TABLES_CLEANUP_SECS` (300) closes the Assignments of Matches tesoro_core froze or deleted (`close_assignment`, rent back to the keeper).

`<G>` is `DUEL`, `HOLDEM`, `BURST` or `VANGUARD`. Default caps: 20, 20, 50 (Block Burst on devnet), 20. Alerts (mail, via the existing alert manager): not the operator, no Sponsor, Sponsor low and refill failing, cap reached with Matches waiting, a Match without a table for `KEEPER_TABLE_WAIT_SECS` (300) that the keeper could not refund, a table Over for `KEEPER_TABLES_STUCK_OVER_SECS` (1800) or a result unsettled for `KEEPER_TABLES_UNSETTLED_SECS` (12 h). The per-Match hooks (`duel.ts`, `holdem.ts`, `burst.ts`, `vanguard.ts`) only drive a Match on its table; a test (`end-state.test.ts`) fails if one of them commits, assigns, resets or releases. Fast refunds (ticket 35): a joined Match no table took within 5 minutes (`table_kit::TABLE_WAIT_SECS`, mirrored in `scheduler.ts`) is refunded with the Game's `refund_untabled`, after the assignment pass has had its chance; an Assignment whose start window closed with its table still Idle at its epoch is given up with `skip_epoch`, which writes a Draw into the ring so the table's next commit lets `finalize` refund it. The keeper never checks in or plays for a Player. `pnpm --filter @tesoro/keeper start --once --dry-run` prints every step as `DRY-RUN would ...` and sends nothing.

## Economy upgrade jobs

Each job is permissionless on chain, bounded per pass, and has a pure plan plus tests (`src/*.test.ts`).

- **history** (`src/history.ts`, `src/events-scan.ts`): lists the transactions that touched core's event authority (every event-CPI of core carries it), oldest first since a cursor (`KEEPER_STATE_DIR/history-cursor.json`), decodes the Match records (`app/src/server/history`, only event-CPIs core itself issued count) and hands each transaction to its sinks: the database (needs `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`, migration 0010 applied) and the notification feed. The cursor moves only past transactions every sink took, so an outage or a restart repeats work and never skips any. `scripts/history-backfill.ts [--from <unix>] [--set-cursor] [--dry-run]` rebuilds the whole history with the same writer. `KEEPER_HISTORY_PER_PASS` (200), `KEEPER_HISTORY_FIRST_PAGES` (3), `KEEPER_HISTORY_SKIP_AFTER` (5 passes before an unreadable transaction is skipped).
- **tickets** (`src/tickets.ts`): cancels Entry and Backing Tickets past `expires_at` (`cancel_ticket`, repeated until Cancelled, with the books of the staged lines' Sources and, for a Backing Ticket, its Offer) and closes Cancelled ones (`close_ticket`).
- **orders** (`src/orders.ts`): `expire_instant_redeem` for orders past `expires_at` (the unsold Gemas go back to the seller). Optional fill rule, off by default: it fills the oldest open orders of Solana Sources only when `EconomyConfig.keeper_fills` is on, this keeper holds `fill_keeper`, and it has a budget (`KEEPER_FILL_MAX_GEMAS` per pass, 0 = off; `KEEPER_FILL_ORDERS_PER_PASS`, 3); the size is the largest a free dry run accepts. EVM orders are filled by the bridge store admin (`instant_redeem_to_evm`), not here.
- **harvest** (`src/counters.ts`): `harvest` moves the ready part of a Source's Leaderboard counter into its custody's prize escrow (only routes with the escrow on). **fees**: `cash_in_fee` for the covered Platform and Studio counters of Solana Sources to `Config.platform_recipient` and `EconomyConfig.tesoro_studio` (their token account is created first). Both look at `KEEPER_COUNTERS_PER_PASS` (25) Sources round robin, only counters of at least `KEEPER_COUNTERS_MIN_GEMAS` (10), and a dry run decides; a Source with nothing ready waits `KEEPER_COUNTERS_RETRY_SECS` (1800).
- **batches** (`src/batches.ts`, `src/bridge-ix.ts`): ETH and HYPE fee cash-ins and prize payouts. Covered counters of EVM Sources go into the route's open batch (`open_batch`, `add_to_batch`); a batch that reached the route minimum or 8 entries is sealed, a sealed one is sent with `send_batch` and sent AGAIN every `KEEPER_BATCH_RESEND_SECS` (1800) until the vault's acknowledgements add up, a Done one is closed. Pending prize payouts are sent again until the vault answers (`send_pay_prize`), a Rejected one is refunded (`refund_prize_payout`), a final one closed. Sends cost a LayerZero fee under the same caps as the bridge job.
- **pools** (`src/pools.ts`): `UpdateStakePoolBalance` for a staking-token custody's pool that is behind this epoch (core refuses to price a payout from a pool more than one epoch old).
- **overflow** (`src/overflow.ts`): a credit that finds no slot in an Account's stores (settle/refund chunks, Season prizes, a full Pool) sits in an overflow record (`["overflow", owner, kind, id]`). The job lists them, and sends `claim_overflow` for each record whose owner has a free slot beyond the held ones (4 lines per transaction, with the Source books of the lines) or that is empty (that closes it: the rent goes back to whoever paid it). With no room it grows the owner's spill by 1 only for a record the keeper itself paid (a Season prize); a Match's lines belong to its Players, so their record waits until they make room. `match` passes the records of the credited Accounts to every chunk; `season` sends the prize through a record (remaining accounts: the record and the system program, the authority pays its rent) when the winner's stores are at the maximum and cannot grow.
- **sweep** (`src/sweeps.ts`): `close_receipt` 14 days after a settlement, `close_pair` once a pair counter's 24 h window ended (pairs are learned from the history feed, so only ones seen since the keeper started). **listing**: for each listed Game whose ProgramData slot moved since approval, `refresh_listing`; `CodeChanged` is never retried and raises an alert to the founders until `list_game` is run with the new hash.
