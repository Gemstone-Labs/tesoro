# Keeper

Off-chain process that keeps the devnet demo moving without a human. Every job is idempotent, permissionless on chain (the keeper is just a fee payer) and logs one line per action.

```
pnpm --filter @tesoro/keeper start            # loop, every 20 s
pnpm --filter @tesoro/keeper start --once     # one pass, then exit
pnpm --filter @tesoro/keeper start --once --dry-run   # say what it would do, send nothing
pnpm --filter @tesoro/keeper typecheck
```

Flags / env: `--interval <secs>` (`KEEPER_INTERVAL_SECS`, 20), `--max-sol-per-hour <n>` (`KEEPER_MAX_SOL_PER_HOUR`, 0.5), `--rpc <url>` (`KEEPER_RPC`, default `https://rpc.magicblock.app/devnet`; the public devnet RPC rate-limits), `KEEPER_KEYPAIR` (`~/.config/tesoro/keeper.json`; `KEEPER_SECRET_KEY` holding the file's JSON array wins when set), `TESORO_IDL_DIR`, `KEEPER_RPC_TIMEOUT_MS` (30000: each RPC request gives up after this), `KEEPER_JOB_LIMIT_SECS` (120: a job still running after this no longer holds up the others and is skipped until it finishes), `KEEPER_YIELD_BUDGET_SHARE` (0.2: share of the hourly cap the yield cranks may use), `KEEPER_YIELD_MIN_GEMAS` (10), `KEEPER_YIELD_MAX_AGE_SECS` (600), `KEEPER_YIELD_MIN_INTERVAL_SECS` (120), `KEEPER_YIELD_MAX_TX` (3 per pass).

Cluster: at startup the keeper checks the genesis hash of `KEEPER_RPC` and `KEEPER_GPA_RPC` and refuses to start unless both are Solana devnet. The Hoodi RPC must answer chain id 560048: a different chain stops the start, an unreachable one is rechecked by the eth job before it sends. The compromised key `AXwY…` (`~/.config/solana/id.json`) is refused as payer or oracle.

Bridge / Ethereum: `--max-lz-fee-sol` (`KEEPER_MAX_LZ_FEE_SOL`, 0.005: refuse a Solana-side LayerZero send whose quote is higher), `--max-lz-sol-per-hour` (`KEEPER_MAX_LZ_SOL_PER_HOUR`, 0.05: LayerZero fees paid in any rolling hour), `--hoodi-rpc` (`KEEPER_HOODI_RPC`, `https://ethereum-hoodi-rpc.publicnode.com`), `--hyperevm-rpc` (`KEEPER_HYPEREVM_RPC`, `https://rpc.hyperliquid-testnet.xyz/evm`), `--max-hype-per-hour` (`KEEPER_MAX_HYPE_PER_HOUR`, 0.03: the same cap for HyperEVM reports, in HYPE), `KEEPER_EVM_ENV` (`~/.config/tesoro/evm-deployer.env`, key `EVM_DEPLOYER_PRIVATE_KEY`, read but never logged; `KEEPER_EVM_PRIVATE_KEY` wins when set), `--eth-yield-mins` (`KEEPER_ETH_YIELD_MINS`, 10 = one simulated month), `--max-eth-per-hour` (`KEEPER_MAX_ETH_PER_HOUR`, 0.005: LayerZero fee + gas the EVM key may spend on reports per rolling hour), `KEEPER_STATE_DIR` (`~/.cache/tesoro-keeper`, last-report times).

Payer: `~/.config/tesoro/keeper.json` is created on first run (never in the repo). The keeper never funds itself: a payer under 0.1 SOL is logged at start and topped up by hand. Fees and rent it spends are tracked in a rolling hour; at the cap, actions are skipped and logged. 429s are retried with exponential backoff inside each RPC call, and the loop doubles its delay (max 5 min) after a rate-limited pass.

## Hosting and liveness

Hosted keys come from env secrets, never from the image: `KEEPER_SECRET_KEY`, `KEEPER_ORACLE_SECRET_KEY` (the JSON arrays of the key files) and `KEEPER_EVM_PRIVATE_KEY` (`src/keys.ts`). `KEEPER_KEYS_FROM_ENV=1` (set in the image) makes a missing `KEEPER_SECRET_KEY` fatal instead of minting a new payer. Each pass logs `alive pass=<n> took=<s>`; a watchdog exits the process when no pass finishes in `KEEPER_WATCHDOG_SECS` (1200), for the host to restart it; `KEEPER_HEALTH_PORT` serves `GET /healthz` (200 alive, 503 stale) on all interfaces, or only on `KEEPER_HEALTH_HOST` when set (e.g. `127.0.0.1` on a VPS with a public IP). Image: `keeper/Dockerfile`; Fly.io config: `keeper/fly.toml`.

## Jobs

1. **Match hygiene** (every Match in tesoro_core that is not Settled or Refunded; Block Puzzle in `src/blockpuzzle.ts`, Hold'em in `src/matches.ts`)
   - Block Puzzle (open_session / join_session flow; the Seed lives in a SeedVault in the TEE, so the keeper never needs it):
     - Open Match nobody joined, Queue window (1 h) over: `refund_match`. Its opener Board and SeedVault stay delegated (the rollup cannot see the base Match).
     - Joined on tesoro_core but not bound to the Session (an older client): `join_session`, inside the Match's 1 h window; after it, `refund_match`.
     - Both Boards in the rollup: a free simulation of `seal` (works from a non-member) says whether both runs are closed. If so, or if both deadlines passed, `seal` + `commit_boards` in the TEE, then `settle` on the base layer (one pass). Otherwise it logs when the deadlines fall.
     - A Board still on the base layer (its Player never delegated) whose deadline passed (opener: the Queue window, joiner: 24 h): `delegate_opener` / `delegate_joiner`, then seal + commit + settle: that Player forfeits, per the program. Before every seal the keeper reads the two Board permissions and the SeedVault permission in the rollup and creates any that is missing, each as its own retried step: `commit_boards` closes all three in the same transaction as `seal`, so one missing permission fails both.
     - Neither Board delegated and the joiner's 24 h deadline passed: `claim_timeout` (both forfeit, both entries refunded). Both committed and sealed but not settled: `settle`.
     - A Session in the pre-`open_session` layout (cannot be decoded by the current program) or a joined Match with no Session: waits for the Match deadline, then `refund_match`.
     - Rollup attempts per Match are throttled to one a minute.
   - Hold'em: a finished (over or cancelled) table on the base layer: `finalize`. A table left in Created on the base layer (the client exited before `delegate_match`): `finalize` once its 5-minute start deadline has passed, which refunds both entries (tesoro_core's own deadline is 24 h out). A delegated table is private to its Players, so the keeper simulates `claim_timeout` (idle Player past deadline) and `close_match` (table finished) in the rollup and sends what would succeed, then `finalize`. A table that never went live, or no table, past the Match deadline: `refund_match`. It never refunds a live delegated table.
   - Trading Duel (`src/duel.ts`, pure decision in `duelStep`; the Duel is public in the rollup, so the keeper reads it with its own token): no Duel past the Match deadline: `refund_match`. On the base layer: over or cancelled and not finalized: `finalize` (a draw refunds); Created and never delegated past its 5-minute start deadline: `finalize` (refund). In the rollup: Created past the start deadline: `claim_timeout`; Live and `ends_at` + `KEEPER_DUEL_END_GRACE_SECS` (2, so the Players' clients try first) passed: `end_match` (reads no price, so the result is the same whoever ends it; a free simulation first, and if the rollup clock is still behind and refuses, the keeper retries next pass); Over or cancelled: `close_match` then `finalize`. Needs no extra env; the Duel IDL is loaded like the others (`target/idl/trading_duel.json` or the app's copy).
2. **Backing hygiene**: `expire_offer` for Open Offers past `expires_at` and Accepted Offers past `use_by`, releasing the Backer's reservation. Requests have no expiry instruction in tesoro_core (only the Player can `cancel_request`) and hold no reservation, so they are only counted.
3. **Price feed** (`src/price.ts`): the oracle key (`KEEPER_ORACLE`, `~/.config/tesoro/oracle.json`) publishes SOL/USD with `set_price` whenever the on-chain `PriceFeed` is older than 50 minutes (`KEEPER_PRICE_REFRESH_SECS`; so at least hourly; Advances reject a feed older than 24 h). Price: Pyth Hermes (update at most 2 minutes old, confidence within 2%), CoinGecko and Coinbase spot are all asked; two or more valid answers give their median, a single one is used only within 25% of the last on-chain price. With no usable price nothing is published, so the feed ages and Advances stop at 24 h rather than being priced from a re-stamped old value. It is a **devnet price feed**, a stand-in until Pyth is read on chain. The oracle pays that fee, so keep it funded.
4. **Yield** (`src/yield.ts`): a Solana-native Position (simSOL custody, `source_asset == SIM_SOL_MINT`) that is Locked with Debt > 0 (`open_advance` set) gets `accrue_native_yield` when the crank is worth it, at most every `KEEPER_YIELD_MIN_INTERVAL_SECS` per Position unless it repays the whole Debt: it would repay at least `KEEPER_YIELD_MIN_GEMAS` Gemas or the whole Debt, or it repays something and the Position was last cranked over `KEEPER_YIELD_MAX_AGE_SECS` ago. The gain is computed off chain from the pool rate, the custody's `tracked_shares` and the open Source, exactly as the program applies it. Up to 4 Positions share a transaction (a failed batch sends its Positions alone afterwards), at most `KEEPER_YIELD_MAX_TX` transactions a pass, within the job's share of the hourly cap. The gain is net of the Treasury's Yield Fee (20%, read from the Treasury account each pass; the job skips until `init_treasury` has run). Each instruction uses the real accounts `[position, custody, vault, pool, mint, yield config and authority, sim_lst, token program, treasury, treasury vault, open Advance source]` built by `app/src/lib/chain/native.ts` (shared with the app). Simulated yield: 1 month = ~10 min.
5. **Bridge relays, Solana side** (`src/bridge.ts`, `src/lz.ts`; flow in `docs/cross-chain.md`). Reads every `BridgePosition` and `Claim` of `tesoro_bridge` and moves what is ready, each step guarded by the bridge's own tracking (`opened`, `applied_yield_seq`, `unlock_sent`, `Claim.units_sent`), so a repeated pass is a no-op:
   - PositionLocked delivered, not applied: `apply_locked` (the keeper pays the core Position's rent; waits, with a log line, while the owner's EVM address is not linked to an Account).
   - YieldAccrued delivered and newer than the applied one: `apply_yield` (with the Position's open Advance Source, if any).
   - Position Unlocked in `tesoro_core` with Debt zero: `send_unlock`. Redemption Claim with units not yet sent (`redeem_to_evm`): `send_pay_yield`.
   - The two sends pay the LayerZero fee in SOL from the keeper payer: the fee is quoted by simulating `quote_send`, refused above `--max-lz-fee-sol`, and counted against `--max-lz-sol-per-hour`. Every base transaction is simulated first, so a step that would fail is logged as `wait: ... would fail (...)` and costs nothing.
6. **EVM yield** (`src/eth.ts`): each Ethereum (Hoodi) or HyperEVM testnet Position that is Locked with Debt gets `PositionVaultOApp.reportYield(id)` every `--eth-yield-mins` (10), paying the vault's `quoteYieldAccrued()` + 20% from the EVM deployer key (the excess is refunded). The send is recorded (state file, and the hourly ETH cap at its estimated cost) as soon as the transaction is out; its receipt is read on a later pass, never waited for, so a slow receipt cannot cause a second send. A send with no receipt that the node no longer knows after 15 minutes is taken as dropped and sent again. Skipped: a Position reported inside the window or whose send has no receipt yet (state file), one whose last message is still in flight (vault `outSeq` above the bridge's `last_in_seq`, unless it has been stuck for 3 windows), an unlocked one, and everything once `--max-eth-per-hour` is used. Delivery to Solana takes about 2 minutes, then the bridge job's `apply_yield` lowers the Debt. Hoodi and HyperEVM have separate RPC checks (chain id 560048 / 998), caps and budgets: a HyperEVM report costs HYPE (about 0.0074 per message), so its cap is `--max-hype-per-hour`.

Fixture: `pnpm --filter @tesoro/keeper exec tsx scripts/both-runs-closed.ts` plays a real devnet Block Puzzle Match up to "both runs closed" (test wallets from `~/.config/tesoro/block-puzzle-testers.json`) and stops, so the keeper does the seal, commit and settle.

## Sharing

The keeper imports the app's IDL-based clients (`app/src/games/*/chain.ts`) and IDL JSON directly, so it cannot drift from them. It only needs `app/` to be installed (`pnpm install` at the root).

## Limits

- Private rollup state (Block Puzzle Boards, Hold'em tables) is unreadable to the keeper; it uses simulations and program-enforced clocks to decide. If the rollup rejects simulation from a non-member, the keeper waits for the deadline paths.
- Block Puzzle Matches are settled by the Player clients when they can; the keeper is the fallback. The forfeited-Board path (`delegate_*` + permission for a Player who never delegated) needs a 24 h wait (opener: 1 h) and is implemented from the app's `bringForfeitedBoardsIn` and the program, but not yet exercised on devnet.
- Wallet-signed steps stay with the user: `create_account`, `link_evm`, `take_advance` (owner + oracle), `redeem_to_evm` and `unlock`. Once they exist, the keeper does everything after them.
- `init_position` (the inbox record that must exist before `openPosition`) is not pre-created by the keeper; the app does it.

7. **Leaderboard seasons** (`src/season.ts`, ADR 0006): once a season has ended (plus `KEEPER_SEASON_GRACE_SECS`, 600, so late settlements are in) and `Config` has a pool, recompute its table from the pool Account's `MatchWon` history, record the top ten with `record_season`, then pay each unpaid rank with `pay_season_rank` (one transaction per rank, pool Holdings drained in Source order, the winner's missing Holdings opened in the same transaction). Signed and paid by the oracle key (`Config.oracle_authority`), so keep it funded: about 0.0032 SOL of rent for the `Season` account, about 0.00005 SOL of fees per transaction (up to 11 a week), plus 0.0011 SOL for each winner Holding that does not exist yet (usually 1 to 3 per winner: under 0.04 SOL in a busy week). Looks back four seasons; a season with no wins is rechecked every 30 minutes. Idempotent: a recorded season is never recomputed and a paid rank never paid twice.
8. **Treasury** (`src/treasury.ts`): the Treasury Account holds the Gemas bought by Instant Redeem. When their Source's yield has repaid them (the normal pro rata Redeem rule), the job redeems them at full value: `redeem_treasury` for Solana Sources (simSOL into the treasury vault), bridge `redeem_treasury_to_evm` for ETH and HYPE Sources, whose Claim the bridge job then pays into the vault's own treasury with `send_pay_yield` (no EvmLink). Bounded: `KEEPER_TREASURY_MAX_PER_PASS` (4) redeems of at least `KEEPER_TREASURY_MIN_GEMAS` (100) Gemas per pass. Set the Treasury up and fund it once with `keeper/scripts/fund-treasury.ts`.
